# Управление VPNAI 0.5.1

Приложение управляет реальными серверами по SSH. Демонстрационного режима нет.

## Запуск

Используйте готовую сборку своей ОС. Для исходников сначала установите зависимости командой подготовки из папки app, затем запустите macos.command, linux.sh или windows.bat.
Открывайте полный адрес, показанный при запуске: часть после `#` даёт доступ к локальному API.

В основном разделе «Подключение» введите публичные IPv4 и SSH-доступ root к обоим серверам. Поддерживаются пароль, приватный ключ и локальный ключ. На обоих серверах нужен Python 3; VPN уже должен быть установлен актуальной версией VPNAI.
Сверьте SSH-отпечатки и подтвердите доверие. Смена ранее подтверждённого ключа блокирует соединение. Доверие и доступ хранятся в памяти текущего запуска.

## Действия

- «Управление»: пользователи, комментарии, активные UDP/TCP-сессии, IP клиента, VPN-адрес, длительность и трафик текущих сессий. При нескольких сессиях показаны все адреса и длительности; IP, VPN-адрес, длительность и трафик показаны отдельно для каждой сессии. Обновление каждые 30 секунд и вручную. Истории и показателя «трафик за сегодня» нет.
- «Управлять → Пароль, комментарий и QR-код»: чтение проверенного действующего пароля, генерация нового локально, ручная смена и комментарий. Пустой пароль означает «не менять». QR создаётся на компьютере без внешних сервисов. Изменённый пароль применяется только при сохранении и отключает активные VPN-сессии командой ovpn-user.
- Создание пользователя выпускает сертификат и профили. Удаление требует ввода логина и отзывает сертификат.
- «Конфигурации»: ZIP для одного или всех активных пользователей; временная HTTPS-ссылка с сервера через ovpn-link.
- «Маршрутизация»: чтение IPList, RU-EU и RU, добавление и удаление ручных IPv4/CIDR, обновление IPList командой ovpn-routing. После изменений переподключите VPN-клиенты.

Операции выполняются через существующие `ovpn-user`, `ovpn-custom`, `ovpn-routing`, `ovpn-link`, с блокировками установки и пользователей. Установка и администрирование в приложении не выполняются одновременно. На сервер не устанавливается новый веб-сервис.

Если команда изменила пароль, а сохранение комментария не удалось, приложение явно сообщает о частичном результате. Если изменение выполнено, но последующее обновление статуса не удалось, приложение сообщает об этом отдельно; не повторяйте изменение вслепую.

## Проверки

`app/.venv/bin/python -m unittest discover -s app/tests -v`

Тесты проверяют API, валидацию, SSH-транспорт, отправку паролей через stdin, чтение пароля с проверкой хеша, сохранение комментария, ZIP и защиту запросов. Проверка на реальной паре VPS выполняется пользователем после ввода доступа. Реальные подключения и изменения VPS при разработке не выполнялись.


## Сеанс подключения и SSH-алиасы

Данные формы «Подключение», включая пароль и путь к ключу, автоматически сохраняются только в памяти процесса. Обновление страницы и переход между разделами не очищают форму. Отключение SSH сохраняет форму до завершения приложения. Закрытие приложения очищает её. Данные доступа не записываются в localStorage или на диск.

Кнопка со стрелкой в поле IP-адреса открывает список конкретных `Host`-алиасов SSH-конфигурации. Выбор подставляет публичный IPv4, SSH-порт, root и IdentityFile, если он указан. Доменное имя разрешается в IPv4 при выборе; неоднозначный или непубличный адрес требует ручного ввода. Пароль и пароль ключа предыдущего сервера при выборе другого алиаса очищаются.

Источники: macOS/Linux — `~/.ssh/config`, затем `/etc/ssh/ssh_config`; Windows — `%USERPROFILE%\.ssh\config`, затем `%PROGRAMDATA%\ssh\ssh_config`. Поддерживаются `Include`, несколько имён в Host, шаблоны и отрицания, первый заданный параметр имеет приоритет. Файлы ключей при показе списка не читаются. Match-команды не исполняются; при Match-блоках или ProxyJump/ProxyCommand/CertificateFile алиасы недоступны для автоматического подключения, причину видно в списке. Подключение VPNAI требует root.

Расположение файлов и порядок обработки сверены с [OpenSSH ssh_config](https://man.openbsd.org/ssh_config) и [документацией Microsoft](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh-server-configuration).


Статус GRE / IPsec справа от поиска проверяется вместе с обновлением управления: интерфейс gre-nl, его зарубежный адрес, установленная GRE CHILD_SA и ответ ping через gre-nl. При успехе отображается задержка. Проверка не запускает восстановление или перезапуск служб.


Раздел «Установка»: вариант «Обновить/Восстановить → Обновить текущую конфигурацию» применяет настройки формы и списки с сохранением пользователей. Нового пользователя создаёт только если их нет. Защитные копии создаются перед записью.


Действия диагностики в разделе «Установка» и зелёный статус административного подключения — разные наблюдения. Диагностика может работать со старой установкой без state.json; управление требует совместимых ovpn-команд и данных пользователей. Для диагностики не требуется предварительный успех кнопки «Подключиться»: заполненные данные общей формы используются при запуске проверки.

## DNS для VPN-клиентов

Общая настройка DNS доступна в «Управление → Маршрутизация»; при установке/обновлении включается отдельно. Google, Cloudflare или свои публичные IPv4. Применение требует подтверждения, перезапускает активный OpenVPN и требует переподключения клиентов. Чтение и проверка доступности не применяют настройки. «DNS клиента» отменяет выдачу DNS; «Не менять при установке» сохраняет действующие настройки. Подробности: [DNS.md](DNS.md).


## Изменения 0.5.1

При выборе «Обновить/Восстановить» текущие параметры, списки и DNS считываются автоматически. В «Маршрутах» показываются адреса с сервера, автоматическое чтение сохраняет ваши правки. Открытие «Управления» обновляет состояние и DNS; ручные кнопки чтения остаются. Для установок без state.json/owned.json поддержаны чтение и ограниченная смена входа/DNS, а не полное обновление компонентов: [подробнее](LOCAL_LEGACY.md). Ошибка отсутствия метаданных сама по себе больше не мешает читать известную конфигурацию.

Штатное завершение/ошибка/отмена освобождают SSH-блокировку; при обрыве связи аренда истекает через 45 секунд, если команда уже завершилась. Действующая команда остаётся защищённой. Файл блокировки вручную удалять не нужно.


## Лимиты подключений 0.5.1

Общий лимит — в установке и «Управление → Маршрутизация»; индивидуальный — в меню пользователя. Первый запуск функции на старой установке потребует переподключить устройства после подтверждения. Дальнейшее уменьшение лимита сохраняет текущие сеансы. Подробнее: [CONNECTION_LIMITS.md](CONNECTION_LIMITS.md).
