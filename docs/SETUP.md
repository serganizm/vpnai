# Гайд по настройке VPNAI

## 1. Запустите приложение

1. Скачайте **VPNAI-vX.Y.Z.zip** из раздела **Releases → Assets** и полностью распакуйте его. Не запускайте файлы прямо внутри ZIP.
2. Установите Python 3.9+ с [python.org](https://www.python.org/downloads/). На Windows отметьте Add Python to PATH.
3. Запустите `macos.command`, `bash linux.sh` или `windows.bat` в зависимости от системы.
4. Приложение откроется в браузере. Если браузер не открылся, скопируйте полный адрес из окна запуска, включая часть после `#`.

Для первого знакомства оставьте демонстрацию включённой: адреса серверов и пароли не нужны. Пройдите четыре шага и запустите демонстрацию. Архив примера не содержит работающих профилей VPN.

## 2. Подготовьте два VPS

| Что требуется | Значение |
|---|---|
| ОС | Ubuntu 24.04/26.04 или Debian 12/13 |
| Доступ | root по SSH, пароль или ключ |
| Адреса | Два разных публичных IPv4, назначенных интерфейсам напрямую |
| Основной маршрут | Один однозначный default route на каждом сервере |
| Российский сервер | Свободный выбранный порт OpenVPN по UDP и TCP; TCP 80/443; локальный TCP 8765 |
| Межсерверная связь | UDP 500/4500, ESP и GRE в IPsec должны пропускаться сетью |

Серверы за NAT пока не поддерживаются. Разрешите нужные порты также в firewall панели провайдера. TCP 80 нужен для проверки HTTPS-сертификата, TCP 443 — для временных ссылок на профили; не выбирайте занятый SSH-порт в качестве порта OpenVPN.

Если Python 3 отсутствует, приложение установит его на сервер при установке/восстановлении. Это не заменяет Python на вашем компьютере, необходимый для самого приложения.

## 3. Установите SSH-компонент на компьютере

Из корня проекта:

| Система | Команда или файл |
|---|---|
| macOS | `bash app/setup-ssh-macos.command` |
| Linux | `bash app/setup-ssh-linux.sh` |
| Windows | `app\setup-ssh-windows.bat` |

Перед запуском скрипта закройте приложение и окно его запуска. На Windows откройте папку `app` и дважды щёлкните `setup-ssh-windows.bat`. Дождитесь сообщения «Готово», затем снова откройте `windows.bat` из основной папки. Для скачивания библиотеки нужен интернет.

Скрипт создаёт `app/.venv` и устанавливает Paramiko из `app/requirements.txt`. После этого перезапустите приложение обычным файлом запуска. Для демонстрации этот шаг не нужен.

## 4. Введите данные серверов

1. Отключите «Попробовать без серверов».
2. Введите IP и SSH-порт российского и зарубежного серверов. Пользователь — root.
3. Выберите способ входа:
   - **Пароль** — введите пароль SSH.
   - **Вставить приватный SSH-ключ** — вставьте ключ, при необходимости пароль ключа.
   - **Мой локальный ключ / скопировать на сервер** — укажите путь к приватному ключу без `.pub`.
4. При запуске операции приложение автоматически получит SSH-ключи. Для новых серверов подтвердите доверие один раз; по возможности сверьте отпечатки через консоль хостинга. Доверенные ключи затем проверяются автоматически.

### Если публичного ключа ещё нет на сервере

В режиме локального ключа заполните IP/порт и нажмите «Показать команду». ОС определяется автоматически, её можно поменять вручную. Скопируйте команду и выполните **на своём компьютере**, а не внутри SSH-сеанса.

Пример для macOS/Linux с тестовым адресом:

```bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub -p 2222 root@198.51.100.10
```

Заменять параметры вручную в приложении не нужно: команда строится из формы. На Windows выводится вариант PowerShell с добавлением `.pub` в `authorized_keys` Linux-сервера. Если `ssh-copy-id` не установлен, интерфейс показывает альтернативу через обычный SSH.

Приложение команды копирования автоматически не выполняет и не создаёт SSH-ключи. Публичный ключ копируется на сервер, приватный остаётся на компьютере. Альтернативная команда при повторном выполнении может добавить дубликат строки ключа.

## 5. Проверьте серверы

На шаге «Настройки VPN» выберите «Проверить серверы» и запустите операцию из сводки. Проверяются доступ, поддержка ОС, Python, адреса и конфликты установки.

Проверочные действия пакеты не устанавливают и не обновляют. Если Python отсутствует, отчёт покажет, что полная проверка не выполнена; выберите установку/восстановление для автоматической подготовки Python.

## 6. Выберите установку и режимы

После проверки нажмите «Новая операция» и выберите:

| Действие | Когда использовать |
|---|---|
| Установить | На новой паре, где нет сохранённой установки |
| Восстановить | После незавершённой установки или для повторного применения сохранённых настроек |
| Проверить VPN | Для проверки уже установленной системы |
| Установить заново | Удалить пользователей и настройки этой установки и начать с нуля |
| Удалить установку | Удалить только компоненты, которыми владеет установщик |

Удаление и установка заново требуют слова **УДАЛИТЬ** и сохранённых данных владельца на обоих серверах. Перед ними создаётся закрытый резервный архив в `/root/ovpn-backup-*.tar.gz` на каждом сервере. Чужие конфигурации и занятые порты останавливают установку.

### Маршрутизация

- **Раздельные маршруты:** IPList и RU-EU → зарубежный; RU → российский; остальные IPv4 напрямую.
- **Весь трафик через VPN:** IPList и RU-EU → зарубежный; RU и остальные IPv4 → российский.
- **Весь трафик через зарубежный:** все внешние IPv4 выходят через зарубежный сервер. Ручные списки сохраняются, но на выход не влияют.

### Вход пользователей

- **Сертификат + пароль:** отдельный сертификат, логин и пароль для каждого пользователя.
- **Только сертификат:** индивидуальный `.ovpn` без ввода логина и пароля; доступ отзывается через сертификат.

Восстановление сохраняет ранее выбранные режимы. Для смены режима авторизации или маршрутизации текущая версия предлагает установку заново, с удалением пользователей и перевыпуском профилей.

### Остальные поля

- Первый пользователь: латинские буквы, цифры, `_` и `-`, до 48 символов.
- Комментарий: необязателен, до 200 символов.
- Порт: 1024–65535, кроме 4500 и 8765; используется одновременно для UDP и TCP и должен быть свободным для обоих протоколов.
- **Обновить пакеты на серверах?** Да/Нет, по умолчанию Нет. При Да выполняется общее `apt-get upgrade`; существующие конфигурационные файлы сохраняются. При Нет необходимые пакеты Python/VPN и их зависимости всё равно устанавливаются.

Обновление ОС применяется только при установке, восстановлении и установке заново. Автоматической перезагрузки нет; необходимость перезагрузки отображается в отчёте. Обновлённые пакеты ОС при откате VPN не возвращаются к старым версиям.

## 7. Заполните ручные списки

Оба поля изначально пусты. Введите нужные публичные IPv4 или CIDR по одной записи в строке; комментарии после `#` допустимы.

- **RU-EU:** дополнительный ручной список выхода через зарубежный сервер.
- **RU:** ручной список выхода через российский сервер; приоритетнее обоих списков RU-EU.

Не включайте адреса самих серверов в ручной RU-EU. Адрес российского VPN-сервера исключается из маршрутов внутри собственного туннеля. Приватные/локальные сети в ручные публичные списки не принимаются.

IPList загружается автоматически с сайта отдельно от этих списков. При восстановлении существующие ручные списки на сервере сохраняются; форма их не перезаписывает.

## 8. Запустите и дождитесь результата

Проверьте сводку на четвёртом шаге, затем запустите операцию. В журнале видны этапы: SSH → ОС/Python → проверки → опциональные обновления → пакеты → PKI/списки → IPsec → HTTPS → OpenVPN → проверки выходов.

Вкладку можно закрыть; окно запуска и компьютер должны продолжать работать. Остановка происходит между этапами: текущая SSH-команда сначала завершится. При ошибке установщик пытается откатить настройки этой незавершённой установки; данные пользователей и ключи сохраняются для восстановления.

Штатный Ctrl+C запрашивает остановку и ждёт её завершения. После принудительного завершения процесса или обрыва сети сначала проверьте серверы, затем используйте восстановление.

## 9. Скачайте профили и проверьте клиент

1. Скачайте архив после успешной операции. В памяти приложения он доступен 10 минут; затем можно получить файлы на российском сервере из `/root/ovpn-profiles/`.
2. Импортируйте `имя-UDP.ovpn` или `имя-TCP.ovpn` в OpenVPN Connect.
3. Если выбран вход по паролю, возьмите данные из `имя-credentials.txt` и сохраните их в профиле клиента.
4. Проверьте нужные сайты, выходы по спискам и прямой путь вне списков со своего устройства.

Серверные проверки не заменяют проверку OpenVPN Connect в вашей сети. Маршрутизация реализована для IPv4: IPv6 остаётся прямым и может обходить эти списки. DNS-настройки устройства не заменяются.

## 10. Управляйте пользователями и маршрутами

Подключитесь к российскому серверу:

```bash
ssh root@IP_РОССИЙСКОГО_СЕРВЕРА
cd /root
./menu.sh
```

Для нестандартного SSH-порта:

```bash
ssh -p ПОРТ root@IP_РОССИЙСКОГО_СЕРВЕРА
```

В меню есть «Пользователи» и «Маршрутизация» с подразделами RU-EU IPList, RU-EU и RU. Назад/выход — `[0]` или Enter. После изменения списков переподключите OpenVPN для получения новых маршрутов.

## Если что-то не получилось

- **Приложение не запускается:** проверьте Python и запуск из полностью распакованной папки.
- **Не установлен SSH-компонент:** выполните `app/setup-ssh-<ОС>.*` и перезапустите приложение.
- **SSH-отпечаток не совпадает:** остановитесь и сверьте ключ сервера в консоли провайдера.
- **Занят порт/есть чужая настройка:** устраните конфликт или используйте отдельную пару VPS; установщик её автоматически не перезаписывает.
- **Не выпущен HTTPS-сертификат:** проверьте доступность TCP 80 извне и `/var/log/letsencrypt/letsencrypt.log`.
- **Ошибка пакетов или службы:** сохраните отчёт приложения и проверьте журналы APT/systemd на сервере. Сырой вывод команд в интерфейс не публикуется, чтобы не раскрыть секреты.
- **После обновления файлов не видно новой опции:** завершите локальное приложение и запустите заново.

Не публикуйте файлы `.ovpn`, `credentials.txt`, SSH-ключи и резервные архивы с серверов в GitHub.


## Повторная проверка старой установки (v0.1.4)

1. Скачайте новый архив, распакуйте в отдельную папку и закройте старое приложение.
2. Установите SSH-компонент в новой папке app скриптом для своей ОС.
3. Запустите приложение, введите данные двух серверов. При запуске ключи получатся автоматически; при первом обращении подтвердите доверие.
4. Выберите «Проверить VPN». Это проверка существующей установки, а не перевод
   её в выбранный в форме режим. В сводке появятся обнаруженные настройки.
5. Для старой установки с полным IPv4-туннелем отсутствие split-status.json
   не является ошибкой. Для раздельного режима этот файл обязателен.
6. Если проверка пройдена, скачайте отчёт и проверьте клиент на своём устройстве.

«Восстановить» сохраняет фактический режим и требует выбрать его в форме.
Переход старой установки с полного туннеля на раздельный режим эта версия
автоматически не выполняет. Не выбирайте установку заново только ради
проверки: она затрагивает существующие данные и требует подтверждения.

Веб-проверка не перезаписывает серверный отчёт, но функциональные тесты
временно создают namespace, интерфейс и правила с последующей очисткой.


SSH-доверие хранится локально в `~/.vpnai/ssh-hosts.json` (Windows: `%USERPROFILE%\.vpnai\ssh-hosts.json`). Там только адреса, порты и публичные отпечатки. Изменённый ключ останавливает подключение до передачи пароля. Правила первого доверия и переустановки сервера: [SSH_TRUST.md](SSH_TRUST.md).
