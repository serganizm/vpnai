# Настройка

1. Подготовьте российский и зарубежный VPS: Ubuntu 24.04/26.04 либо Debian 12/13,
   публичные IPv4 напрямую на интерфейсах, root-доступ по SSH.
2. Запустите VPNAI и введите адреса, порты, пароли или ключи обоих серверов.
3. Выберите действие. Для новой конфигурации — «Установить»; для продолжения
   текущей или выбора парного архива — «Обновить/Восстановить».
4. Выберите маршрутизацию и способ входа пользователей.
5. При обновлении пользователь создаётся только если нет неудалённых пользователей.
   Для новой установки и восстановления из архива укажите логин в форме.
6. Выберите обновление системных пакетов. Необходимые VPN-компоненты и Python
   устанавливаются независимо от общего обновления. Перезагрузка не выполняется.
7. Заполните ручные публичные IPv4/CIDR, если они нужны. Пустой список допустим.
8. Проверьте итог. Для удаления, установки заново или восстановления из архива отметьте флажок после
   прочтения описания изменений на обоих серверах.
9. Запустите операцию, подтвердите SSH-доверие в текущем сеансе и дождитесь результата.
10. Скачайте архив и импортируйте UDP либо TCP-профиль в OpenVPN Connect.

## Порты

| Сервер | Назначение |
|---|---|
| Российский | Выбранный порт OpenVPN UDP/TCP, HTTP 80, HTTPS 443, локальный 8765 |
| Оба | SSH-порт, IPsec UDP 500/4500 |
| Зарубежный | Служебный TCP 18765 только внутри защищённого туннеля |

Проверьте firewall провайдера. HTTP 80 нужен и после установки для продления
сертификата. Штатный nginx после удаления своей конфигурации может использоваться
повторно; чужие веб-службы и конфликты портов не обходятся автоматически.

## Данные текущего сеанса

Новая операция и перезагрузка вкладки сохраняют введённые IP и пароли только
пока процесс приложения работает. Выход очищает их. Никаких автоматических
файлов с паролями, адресами или базой SSH-доверия не создаётся.

## Управление сервером

```sh
ssh root@IP_РОССИЙСКОГО_СЕРВЕРА
cd /root
./menu.sh
```

Персональный архив: `openvpn-ЛОГИН.zip`; общий: `openvpn-all.zip`.
Управление, маршруты и продление HTTPS подробно описаны в [readme.md](readme.md).

## Выбор резервной копии

Для восстановления из копии выберите «Обновить/Восстановить», загрузите список архивов
и выберите архив на российском сервере. Соответствующая зарубежная копия
определяется автоматически. Используется только новый парный формат с одинаковым
именем на обоих серверах. Перед заменой подтвердите действие флажком.

Справка: [readme.md](readme.md).

Основные разделы: «Подключение», «Установка», «Управление». В установке три пункта: настройки VPN, маршруты, запуск. Справка и меню «Файл» над содержимым. «Назад» слева, продолжение справа; кнопки закрытия нет. Desktop завершается Ctrl+C в окне запуска после окончания операции.


Обновление действующей конфигурации: сначала загрузите текущие настройки и списки
с сервера, затем измените их в форме. Применяются маршрутизация, способ входа, порт
и ручные списки; обновляются серверные файлы и меню. Пользователи и сертификаты
сохраняются; новый пользователь создаётся только если нет неудалённых пользователей.
Перед записью создаются парные защитные архивы; изменение конфигурации после
загрузки останавливает запуск до записи. Службы перезапускаются: скачайте новые
профили и переподключите устройства. Существующие действующие пароли сохраняются.
При включении парольного входа для пользователей без сохранённого действующего
пароля создаются новые пароли; имена указаны в отчёте, пароли — в архиве профилей.
При ошибке обновления используйте защитную пару архивов; автоматическое удаление
компонентов в этом случае не выполняется.


Для проверки существующего VPN используйте действия «Проверить серверы»/«Проверить VPN» в разделе «Установка». Они только читают состояние, не требуют служебных файлов установщика и не применяют правила конфликтов новой установки. Их ограничения описаны в readme.md. Отсутствие state.json не даёт права автоматически обновлять или удалять действующий VPN. На чистом сервере форма административного подключения может не сработать: заполните данные и перейдите непосредственно к нужному действию в установке.

## DNS для VPN-клиентов

Общая настройка DNS доступна в «Управление → Маршрутизация»; при установке/обновлении включается отдельно. Google, Cloudflare или свои публичные IPv4. Применение требует подтверждения, перезапускает активный OpenVPN и требует переподключения клиентов. Чтение и проверка доступности не применяют настройки. «DNS клиента» отменяет выдачу DNS; «Не менять при установке» сохраняет действующие настройки. Подробности: [DNS.md](DNS.md).


## Изменения 0.4.1

При выборе «Обновить/Восстановить» текущие параметры, списки и DNS считываются автоматически. В «Маршрутах» показываются адреса с сервера, автоматическое чтение сохраняет ваши правки. Открытие «Управления» обновляет состояние и DNS; ручные кнопки чтения остаются. Для установок без state.json/owned.json поддержаны чтение и ограниченная смена входа/DNS, а не полное обновление компонентов: [подробнее](LOCAL_LEGACY.md). Ошибка отсутствия метаданных сама по себе больше не мешает читать известную конфигурацию.

Штатное завершение/ошибка/отмена освобождают SSH-блокировку; при обрыве связи аренда истекает через 45 секунд, если команда уже завершилась. Действующая команда остаётся защищённой. Файл блокировки вручную удалять не нужно.
