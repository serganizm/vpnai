# Одновременные подключения

Лимит — максимум активных сеансов одного сертификата/пользователя суммарно для UDP и TCP. Счётчик относится к двум экземплярам OpenVPN на российском сервере. Серверы и устройства, не использующие эту пару экземпляров, этим механизмом не управляются.

При новой установке выберите лимит в параметрах VPN (по умолчанию в форме 2). На существующем сервере приложение читает фактическое значение; если функция ещё не установлена, показывается безлимит. В «Управление → Маршрутизация» применяется серверное значение по умолчанию. В меню пользователя можно выбрать индивидуальное число, безлимит или наследование. Индивидуальный лимит привязан к сертификату: новый сертификат с прежним логином наследует общий лимит. Создание обычного нового пользователя не копирует чужое исключение.

Первое включение на действующей установке добавляет обработчики подключения/отключения и перезапускает только ранее активные OpenVPN-службы после явного подтверждения. Все устройства потребуется переподключить: это необходимо для точного начального учёта всех сеансов. Исходные файлы сохраняются в /root/ovpn-limits-backups; при ошибке выполняется откат. Неизвестные пользовательские обработчики не перезаписываются автоматически. Маршруты, DNS, пользователи, пароли и сертификаты не заменяются этой операцией. Последующие изменения записывают политику без перезапуска служб и отключения клиентов.

Уменьшение лимита не разрывает уже открытые сеансы. Новое подключение разрешается только при количестве активных меньше максимума. При потере сети место освобождается после обнаружения отключения OpenVPN, обычно в пределах действующего keepalive (в стандартных конфигурациях до 60 секунд), а не сразу после выключения VPN на устройстве. После остановки/жёсткого перезапуска процесса его старые записи удаляются. Изменение NAT-адреса/порта не создаёт второй слот того же сеанса. Не редактируйте счётчик вручную во время работы.

Политика: /etc/openvpn/server/connection-limits.json (root, 600); временный учёт и блокировка: /run/vpnai-session-limits (root, 700). Удаление политики при активных обработчиках отклоняет новые подключения, а не переключает их в безлимит. Ограничение действует после закрытия приложения; новые .ovpn для изменения лимита не требуются. «—» в бейдже означает, что лимиты не прочитаны, а не безлимит. Защита от одновременных изменений требует перечитать политику при конфликте версии.

Механизм использует client-connect/client-disconnect OpenVPN: https://openvpn.net/community-docs/community-articles/openvpn-2-6-manual/. Тесты используют временные каталоги и моделируют процессы/сеансы; работа на пользовательской паре VPS при подготовке релиза автоматически не изменяется.
