# VPNAI

Локальное приложение устанавливает OpenVPN UDP/TCP на российский сервер,
защищённый GRE/IPsec-туннель на зарубежный и выбранные правила маршрутизации.
Интерфейс работает на компьютере пользователя. Серверные службы продолжают
работать после закрытия приложения.

## Запуск

Запустите готовую сборку для Windows x64, Linux x64 или Mac Apple Silicon.
На macOS/Linux распакуйте архив и откройте исполняемый файл. Браузер откроется
автоматически. Готовой сборке не требуется отдельная установка Python или SSH-библиотек.

В приложении три основных раздела: «Подключение», «Установка», «Управление». В установке три пункта: «Настройки VPN», «Маршруты», «Запуск и результат» (на телефоне «Запуск»). Меню «Файл» и ссылки «Инструкция», «Настройка» находятся над содержимым. Ссылка на GitHub находится
под логотипом и названием приложения.

## Запуск исходников

Готовое приложение содержит Python и SSH-компонент. Для него отдельная
подготовка не нужна. Исходники требуют Python 3.9+ и зависимостей.
Следующие действия выполняются на локальном компьютере, а не на VPS:

- macOS: один раз `app/setup-ssh-macos.command`, затем `macos.command`.
- Linux: один раз `sh app/setup-ssh-linux.sh`, затем `sh linux.sh`.
- Windows: один раз `app/setup-ssh-windows.bat`, затем `windows.bat`.

Подготовка исходников создаёт `app/.venv`; загрузка зависимостей требует
интернета. Готовая исполняемая сборка этот шаг не требует.

## Серверы

Нужны два VPS с Ubuntu 24.04/26.04 или Debian 12/13, root-доступом и публичными
IPv4, назначенными интерфейсам напрямую. Укажите адреса, SSH-порты и пароль
либо ключ. При первом подключении подтвердите SSH-отпечатки. Доверие действует
до завершения приложения; изменение ключа в этом сеансе блокирует подключение.

Все введённые данные хранятся только в памяти процесса. Между операциями
и после обновления вкладки они подставляются автоматически. После закрытия
приложения новый запуск начинается с пустыми полями подключения. Приложение
не создаёт файл с адресами и паролями и не использует браузерное хранилище
для этих данных. Вручную скачанный отчёт содержит адреса серверов, но не пароли.

## Действия

Первая строка: **Установить**, **Установить заново**, **Обновить/Восстановить**.
Вторая строка: **Проверить VPN**, **Проверить серверы**, **Удалить**.

- Установить: создать конфигурацию на подготовленных серверах.
- Установить заново: создать закрытые резервные копии, удалить компоненты
  текущего VPN, пользователей и маршруты, затем установить выбранные параметры.
- Обновить/Восстановить: обновить текущую конфигурацию или выбрать парный архив.
  При обновлении применяются режимы и ручные списки из формы.
  Пользователи и сертификаты сохраняются; новый пользователь создаётся только если их нет.
  При выборе архива текущие данные заменяются сохранёнными. Указанный в форме
  новый пользователь добавляется; активный существующий сохраняет пароль.
- Проверить VPN: прочитать OpenVPN-конфигурации, службы, порты, пересылку IPv4, маршруты VPN, GRE и IPsec SA выбранной пары. HTTPS, сквозные выходы пользовательского трафика и клиентское подключение в этой операции не проверяются.
- Проверить серверы: прочитать SSH, ОС, инвентаризацию и доступные режимы без установки VPN и без применения проверок конфликтов новой установки. Это не разрешение устанавливать поверх существующего VPN.
- Удалить: создать закрытые копии и удалить компоненты текущего VPN на обоих
  серверах. Системные пакеты и резервные архивы сохраняются.

Для удаления, установки заново и восстановления из архива прочитайте описание
на последнем шаге
и отметить флажок подтверждения. Подтверждение не переносится на следующую операцию.

## Маршрутизация

| Режим | Выход трафика IPv4 |
|---|---|
| Раздельные маршруты | IPList и RU-EU через зарубежный сервер; RU через российский; остальное напрямую |
| Весь трафик через VPN | IPList и RU-EU через зарубежный сервер; остальное через российский |
| Весь трафик через зарубежный сервер | Все внешние IPv4 через российский сервер и туннель на зарубежный |

RU имеет приоритет над ручным RU-EU и автоматическим IPList. Ручные списки
изначально пусты. Введите публичные IP/CIDR по одному в строке. IPv6 и DNS
устройства требуют отдельной проверки: эти IPv4-списки не задают их поведение.

IPList автоматически загружается с [сайта](https://iplist.opencck.org/ru/).
На шаге «Маршруты» эта ссылка находится в слове «сайта» под заголовком.
Ручные списки RU-EU и RU при новой установке пусты — добавьте нужные вам
публичные IPv4 или CIDR. При обновлении текущие списки загружаются с сервера
и заменяются отредактированными значениями формы. Пустое поле очищает список.
При восстановлении из архива используются списки из копии.
На телефоне используются переносы текста и карточки. На desktop таблицы могут прокручиваться в своей области.

## Пользователи

Укажите логин в поле «Пользователь для создания». При обновлении он применяется
только если нет неудалённых пользователей. При восстановлении из архива
новый логин создаётся, существующий активный сохраняет пароль.
Отключённый или удалённый логин не включается без отдельного действия администратора.
Установщик проверяет наличие активной записи и обоих UDP/TCP-профилей.

Доступ: индивидуальный сертификат с логином/паролем либо только сертификат.
Один пользователь может иметь несколько одновременных подключений.

Управление после установки:

```sh
ssh root@IP_РОССИЙСКОГО_СЕРВЕРА
cd /root
./menu.sh
```

Для нестандартного SSH-порта добавьте `-p ПОРТ`. Меню позволяет создавать
пользователей, показывать/менять пароли, удалять пользователей, просматривать
подключения, изменять свои маршруты и обновлять IPList.

## Скачивание

В `menu.sh` выберите конфигурационные файлы, пользователя или все конфигурации,
затем способ скачивания. Персональный архив называется `openvpn-ЛОГИН.zip`,
общий — `openvpn-all.zip`. Внутри находятся UDP/TCP-профили и файл доступа.
Ссылка и QR-код действуют 10 минут. Файл доступа содержит секреты — передавайте
архив только тому, кому предназначен доступ.

Скопировать папку профилей на свой компьютер:

```sh
scp -r root@IP_РОССИЙСКОГО_СЕРВЕРА:/root/ovpn-profiles ~/Downloads/
```

Windows PowerShell:

```powershell
scp -r root@IP_РОССИЙСКОГО_СЕРВЕРА:/root/ovpn-profiles "$HOME\Downloads\"
```

Для своего SSH-порта у `scp` используется заглавная `-P ПОРТ`.

## HTTPS и автоматическое продление

Пригодный сертификат используется повторно, если IP совпадает, цепочка доверена,
ключ соответствует сертификату, сохранена конфигурация Certbot и осталось не менее суток.
Приватный ключ и учётная запись ACME остаются на российском сервере.

На зарубежном сервере служба `ovpn-acme-proxy` принимает служебные подключения
только через защищённый туннель от российского сервера. Разрешены только API
Let’s Encrypt на HTTPS. TCP 18765 используется внутри туннеля; открывать его
в панели провайдера не нужно.

Таймер `ovpn-cert-renew.timer` проверяет продление каждый час и после загрузки.
При недоступности служебного канала проверяется прямое соединение. Новый сертификат
выдаётся только когда это требуется Certbot. Ошибка сохраняет текущий сертификат
и не останавливает OpenVPN. При успехе nginx перечитывает сертификат. TCP 80
на российском сервере оставьте доступным для подтверждения IP.

Проверка на российском сервере:

```sh
systemctl list-timers --all ovpn-cert-renew.timer
journalctl -u ovpn-cert-renew.service -n 30 --no-pager
cat /var/lib/ovpn-cert/status.json
python3 /usr/local/sbin/ovpn-cert-manage.py probe
```

`probe` только проверяет доступность API. Таймер работает независимо от приложения.

## Завершение и отчёт

Дождитесь результата и скачайте профили и отчёт. Серверные проверки не заменяют
проверку OpenVPN Connect на устройстве. При ошибке смотрите конкретный этап
в отчёте. Восстановление без архива использует сохранённое состояние настройки.
После удаления для возврата данных выберите парный архив нового формата.
Временные архивы в приложении удаляются из памяти по сроку или при выходе.

## Восстановление из парного архива

Поддерживается только новый формат резервных копий. На обоих серверах создаётся
одинаковое имя: `ovpn-backup-ДАТА-ВРЕМЯ-ID.tar.gz`. Дата и время имени — UTC,
в интерфейсе время отображается по настройкам компьютера. Архивы содержат
общий идентификатор снимка, роли серверов и адреса пары.

1. Введите данные обоих серверов и выберите «Обновить/Восстановить».
2. Загрузите список архивов. Если данные подключения уже введены, список
   запрашивается автоматически после выбора действия.
3. В поле «Архив на российском сервере» выберите нужную копию. Подходящий
   архив на зарубежном сервере будет выбран автоматически по идентификатору,
   имени и соответствию конфигурации туннеля.
4. Режимы и порт подставятся из копии. Свои маршруты будут взяты из неё.
   При необходимости укажите пользователя для создания в восстановленной конфигурации.
5. На итоговом шаге отметьте подтверждение замены данных и запустите операцию.

До изменения конфигурации проверяются оба архива и подготавливаются данные
на обоих серверах. Затем текущее состояние сохраняется в защитную пару с
одинаковым именем. При отсутствии одной копии, несовпадении пары, повреждении,
неподдерживаемых путях или ошибке подготовки замена не начинается.

Из архива возвращаются пользователи, ключи, профили и маршруты. Служебные
программы и определения служб разворачиваются из текущего установщика.
Содержимое архивов не исполняется. Восстанавливать можно только на указанную
в снимке пару адресов. Копия другой пары не предлагается для выбора.

Вариант «Обновить текущую конфигурацию» восстанавливает существующие
настройки. Для него на сервере должно оставаться сохранённое состояние.

Новые копии автоматически создаются перед удалением, установкой заново и
восстановлением из архива. Они хранятся в `/root/` на каждом сервере с правами
600. Пустые защитные копии не предлагаются как варианты восстановления.
Старые архивы не используются и не переименовываются.

Кнопки закрытия в интерфейсе нет. Для остановки desktop дождитесь завершения операции и нажмите Ctrl+C в окне запуска. Закрытие вкладки процесс не завершает. На Android сворачивание сохраняет службу и сеанс; системная остановка процесса очищает его. «Назад» слева, продолжение справа; стрелки на кнопках убраны.


Обновление действующей конфигурации: сначала загрузите текущие настройки и списки
с сервера, затем измените их в форме. Применяются маршрутизация, способ входа, порт
и ручные списки; обновляются серверные файлы и меню. Пользователи и сертификаты
сохраняются; новый пользователь создаётся только если нет неудалённых пользователей.
Перед записью создаются парные защитные архивы; изменение конфигурации после
загрузки останавливает запуск до записи. Службы перезапускаются: скачайте новые
профили и переподключите устройства. Существующие действующие пароли сохраняются.
При включении парольного входа для пользователей без сохранённого действующего
пароля создаются новые пароли; имена указаны в отчёте, пароли — в архиве профилей.
При ошибке обновления используйте защитную пару архивов; автоматическое удаление
компонентов в этом случае не выполняется.


## Диагностика без изменения серверов

Обе проверки не требуют state.json/owned.json: отсутствие служебных файлов выводится как предупреждение. Работающий маршрут VPN не является конфликтом диагностической операции. Подробные результаты — в разделе checks отчёта; passed=true означает успех конкретного наблюдения, false — выявленное замечание, null — неизвестно или недоступно. Поле diagnostics.complete показывает полноту набора наблюдений, healthy — успешность всех доступных пунктов; notice и limitations описывают границы. Проверка с неизвестными пунктами может завершиться технически успешно, но явно помечается неполной и не подтверждает здоровье VPN.

Существующие службы не перезапускаются; серверные файлы, интерфейсы и сетевые пространства не создаются. Ping через существующий GRE отправляет диагностический ICMP-пакет; отсутствие ответа отмечается как неизвестный результат. swanctl проверяет установленную SA к выбранному адресу, но не доказывает защиту каждого GRE-пакета. Подсети и имена служб читаются из найденных конфигураций, а не берутся из параметров новой установки. Если формат старой установки отличается, некоторые пункты останутся неизвестными.

После установки и обновления установщик по-прежнему выполняет более глубокие проверки, в том числе с временными тестовыми сетями. Это часть изменяющей операции, а не обычной диагностики.

## Форма подключения и файл серверов

Через «Файл → Скачать файл» сохраняется пустой JSON-шаблон RU/EU с ip, login=root, password и port. Заполните его и выберите «Загрузить файл»; подходят .json и .txt с той же JSON-структурой. Оба сервера валидируются до подстановки, импорт не запускает подключение. Пароли в заполненном файле открытые.

Общая форма подставляет данные в установку. Кнопка «Подключиться» пока использует команды уже установленного VPNAI. На чистом/старом сервере при отказе этого действия перейдите напрямую к диагностике в «Установке» с заполненной формой — SSH-доверие будет проверено при запуске. Для управления нужны совместимые серверные ovpn-команды.

## DNS для VPN-клиентов

Общая настройка DNS доступна в «Управление → Маршрутизация»; при установке/обновлении включается отдельно. Google, Cloudflare или свои публичные IPv4. Применение требует подтверждения, перезапускает активный OpenVPN и требует переподключения клиентов. Чтение и проверка доступности не применяют настройки. «DNS клиента» отменяет выдачу DNS; «Не менять при установке» сохраняет действующие настройки. Подробности: [DNS.md](DNS.md).


## Изменения 0.4.1

При выборе «Обновить/Восстановить» текущие параметры, списки и DNS считываются автоматически. В «Маршрутах» показываются адреса с сервера, автоматическое чтение сохраняет ваши правки. Открытие «Управления» обновляет состояние и DNS; ручные кнопки чтения остаются. Для установок без state.json/owned.json поддержаны чтение и ограниченная смена входа/DNS, а не полное обновление компонентов: [подробнее](LOCAL_LEGACY.md). Ошибка отсутствия метаданных сама по себе больше не мешает читать известную конфигурацию.

Штатное завершение/ошибка/отмена освобождают SSH-блокировку; при обрыве связи аренда истекает через 45 секунд, если команда уже завершилась. Действующая команда остаётся защищённой. Файл блокировки вручную удалять не нужно.
