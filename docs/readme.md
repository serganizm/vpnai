# OpenVPN · локальный установщик

## Готовый установщик без дополнительных компонентов

Скачайте самостоятельную сборку для своей ОС из Assets релиза: Windows `.exe`, macOS архив для Apple Silicon, Linux архив x64. Запускается один исполняемый файл; Python, Paramiko и setup-ssh на компьютере не нужны. Для macOS/Linux предварительно распакуйте архив. Подробности — [STANDALONE.md](STANDALONE.md). Ссылки на инструкцию и настройку доступны в приложении.

Приведённые ниже шаги с установкой Python и запуском setup-ssh нужны только при выборе архива исходников `VPNAI-source-vX.Y.Z.zip`. Параметры серверов, режимы VPN и управление через menu.sh одинаковы для обеих версий.


## Попробовать без серверов

1. Установите Python **3.9 или новее** с [python.org](https://www.python.org/downloads/), если его ещё нет. На Windows при установке включите **Add Python to PATH**.
2. Распакуйте `VPNAI-vX.Y.Z.zip` в обычную папку на компьютере.
3. Запустите файл для своей ОС:

| ОС | Запуск |
|---|---|
| macOS | Двойной щелчок по `macos.command` в корне VPNAI |
| Linux | В терминале из папки VPNAI: `bash linux.sh` |
| Windows | Двойной щелчок по `windows.bat` в корне VPNAI |

4. В браузере автоматически откроется приложение. Оставьте **«Попробовать без серверов»** включённым.
5. IP, SSH-пароли и ключи в демонстрации не нужны. Перейдите к настройкам, выберите режимы и откройте сводку.
6. Нажмите **«Запустить демонстрацию»**. Посмотрите этапы, скачайте пример архива и отчёт.
7. Для других сценариев нажмите **«Новая операция»**. На первом шаге можно выбрать ошибку или найденную установку. Для найденной установки выберите действие «Восстановить» либо «Установить заново».

Демонстрация ничего не устанавливает, не создаёт SSH-соединения и не выдаёт действующие VPN-профили. В примере архива только пояснение и выбранный план.

Если двойной щелчок на macOS не сработал: откройте Терминал, перейдите в распакованную папку и выполните `bash macos.command`.

## Подключить настоящие серверы

1. Один раз установите SSH-компонент:

| ОС | Установка компонента |
|---|---|
| macOS | `app/setup-ssh-macos.command` или `bash app/setup-ssh-macos.command` |
| Linux | `bash app/setup-ssh-linux.sh` |
| Windows | `app/setup-ssh-windows.bat` |

Компонент устанавливается в `app/.venv`. Для этого нужен интернет. В архив `.venv` не включена.

2. Запустите приложение обычным файлом запуска и выключите демонстрацию.
3. Введите IPv4 и SSH-порт обоих серверов. В этой версии поддерживается вход **root** по паролю, вставленному приватному SSH-ключу или локальному файлу ключа. Для зашифрованного ключа укажите пароль ключа.
4. При запуске операции приложение автоматически получит SSH-отпечатки. Для новых серверов появится одно подтверждение доверия; по возможности независимо сверьте ключи через консоль хостинга. Ручная кнопка и флажок больше не нужны.
5. Выберите действие. Для новой пары сначала удобно выполнить **«Проверить серверы»**, затем новую операцию **«Установить»**.
6. Выберите маршрутизацию и авторизацию, укажите первого пользователя и необязательный комментарий.
7. Ручные списки **RU-EU** и **RU** пусты по умолчанию. Если нужно, введите публичные IPv4 или CIDR — по одной записи в строке. Никакие адреса из прежних проектов не подставляются.
8. Проверьте сводку и запустите операцию. Удаление и установка заново требуют слова **УДАЛИТЬ** и разрешены при наличии данных владельца либо отметки о ранее завершённом удалении этой пары серверов.
9. Дождитесь результата и скачайте архив профилей. В приложении он доступен **10 минут**, затем удаляется из памяти. На российском сервере профили остаются в `/root/ovpn-profiles/`.
10. Импортируйте `-UDP.ovpn` или `-TCP.ovpn` в OpenVPN Connect. Проверьте подключение и нужные сайты со своего устройства.

При восстановлении сохраняются существующие пользователи, ручные списки и режимы. Поля списков при этом не заменяют действующие серверные файлы. Для смены режимов эта версия предлагает установку заново. Меню управления после установки: `/root/menu.sh`.

Перед установкой SSH-компонента закройте приложение и окно его запуска. На Windows откройте папку `app`, запустите `setup-ssh-windows.bat` двойным щелчком и дождитесь сообщения «Готово». После этого запустите `windows.bat` из основной папки. Нужен доступ к интернету; установка выполняется на компьютере, один раз для этой папки приложения.

## Доступные режимы

- **Раздельные маршруты:** IPList и ручной RU-EU → зарубежный сервер; RU → российский; остальные IPv4 → напрямую.
- **Весь трафик через VPN:** IPList и RU-EU → зарубежный сервер; остальные IPv4 → российский. RU имеет приоритет.
- **Весь трафик через зарубежный сервер:** все внешние IPv4 → зарубежный сервер. Ручные списки сохраняются, но на выход в этом режиме не влияют.

Авторизация: индивидуальный сертификат + логин/пароль либо индивидуальный сертификат без ввода пароля. Во втором случае копия профиля даёт доступ к VPN; пользователя отключают отзывом его сертификата через меню.

IPList обновляется отдельно от ручных списков. В раздельном режиме после изменения списков переподключите клиент. **IPv6 остаётся прямым и может обходить IPv4-списки.** DNS-настройки устройства не заменяются.

## Требования к серверам

- Ubuntu 24.04/26.04 либо Debian 12/13 и root-доступ. Если на сервере нет Python 3, установщик установит его автоматически.
- Два разных публичных IPv4, назначенных сетевым интерфейсам напрямую; серверы за NAT в этой версии не поддерживаются.
- Один однозначный основной маршрут на каждом сервере.
- Свободный выбранный порт OpenVPN по UDP и TCP, TCP 80/443 и локальный 8765 на российском сервере; UDP 500/4500 для IPsec.
- Межсерверная передача GRE, защищённого IPsec, должна разрешаться сетью провайдера.
- Для сертификата HTTPS нужен доступ к российскому TCP 80 из интернета.
- Конфликтующие чужие файлы/порты/IPsec останавливают установку, а не перезаписываются автоматически.

## Остановка и данные

- Закрытие вкладки не прерывает операцию. Пока установка идёт, не закрывайте окно запуска и не выключайте компьютер.
- Кнопка остановки действует между этапами: текущая SSH-команда сначала завершится. При незавершённой установке выполняется откат её настроек; пользователи и ключи сохраняются для восстановления.
- При штатном Ctrl+C приложение запрашивает остановку и ждёт её завершения. Принудительное завершение процесса или потеря сети могут оставить частичную установку: сначала проверьте серверы, затем используйте восстановление.
- SSH-пароли и введённые приватные ключи находятся в памяти процесса во время операции. Они не записываются в отчёт, локальные файлы или localStorage. После завершения форма очищает эти поля; после перезапуска их нужно ввести снова.
- VPN-ключи и сгенерированные пароли хранятся на серверах в закрытых файлах, профили можно скачать архивом. Приложение не публикуется в интернет: слушает только `127.0.0.1` и использует временный токен доступа.
- Отчёт показывает этап ошибки. Подробные сообщения пакетов и системных служб смотрите в журнале на сервере; их сырой вывод не публикуется в интерфейс, чтобы не вывести секреты.
- Удаление/установка заново оставляет закрытый резервный архив `/root/ovpn-backup-*.tar.gz` на каждом сервере.

## Что проверено

Автоматические тесты проверяют API, варианты шаблонов, списки и демонстрационные сценарии. Демонстрация также пройдена в браузере. Полная SSH-установка именно этой веб-версии на чистой паре VPS ещё не проверена. Windows и Linux физически в этой сессии не запускались: для них подготовлены файлы запуска, серверная логика общая.

Приложение собрано на основе установочных скриптов, ранее проверенных на рабочей паре. Рабочие серверы при разработке веб-версии не изменялись.

## Мой SSH-ключ и копирование на сервер

1. На первом шаге у нужного сервера выберите **«Мой локальный ключ / скопировать на сервер»**.
2. Укажите путь к приватному ключу без `.pub` (по умолчанию `~/.ssh/id_ed25519`). Если ключ зашифрован, введите пароль ключа.
3. Заполните IP и SSH-порт этого сервера.
4. Нажмите **«Показать команду»**, затем **«Скопировать команду»**.
5. Выполните команду на своём компьютере: в Терминале на macOS/Linux или PowerShell на Windows. При первом входе проверьте отпечаток, затем введите пароль сервера.
6. Вернитесь в приложение и запустите операцию. Получение ключей выполняется автоматически; подтвердите доверие, если сервер ещё не сохранён.

ОС определяется по компьютеру, на котором запущено приложение. Можно вручную выбрать систему команды. Для macOS/Linux формируется `ssh-copy-id`; если его нет, показана альтернатива через обычный `ssh`. Для Windows — команда PowerShell с чтением `.pub` и добавлением в `authorized_keys` Linux-сервера. В обоих случаях сохраняются существующие ключи. Повтор альтернативной команды может добавить повторную строку; доступ это не меняет.

Команды учитывают IP, SSH-порт и выбранный путь ключа. При изменении этих полей старая команда скрывается, её нужно сформировать заново. Приложение не выполняет копирование автоматически. На сервер передаётся только публичный ключ. Приватный ключ читается приложением локально для SSH-аутентификации, на сервер не загружается и в браузер не выводится. Локальный ключ должен уже существовать; приложение не создаёт и не заменяет ваши ключи.

В демонстрации можно указать IP примера, сформировать и скопировать команду, но выполнять её не требуется.

## Подготовка серверов: Python и обновления ОС

После SSH-подключения установщик определяет ОС и наличие Python 3 на обоих серверах. Поддерживаемые версии ОС проверяются до установки пакетов.

При действиях «Установить», «Восстановить» и «Установить заново»:

1. Если Python 3 отсутствует, выполняется обновление индекса APT и установка пакета `python3`.
2. На шаге «Настройки VPN» выберите «Обновить пакеты на серверах?» — Да или Нет (по умолчанию Нет). При выборе Да после проверки конфликтов выполняются `apt-get update` и `apt-get upgrade -y` для каждого сервера. При Нет общее обновление ОС пропускается; индексы APT и необходимые пакеты для Python/VPN устанавливаются по необходимости.
3. Существующие конфигурационные файлы пакетов сохраняются. Учитываются блокировки APT: ожидание до 300 секунд.
4. Устанавливаются компоненты VPN, выполняются настройки и проверки.
5. В сводке и отчёте сохраняется выбор обновления. В отчёте также сохраняются версия Python, факт его установки, факт обновления пакетов и необходимость перезагрузки. Перезагрузка автоматически не выполняется.

«Проверить серверы», «Проверить VPN» и «Удалить установку» системные пакеты не устанавливают и не обновляют. Если при проверке серверов нет Python, приложение сообщает об этом; полная проверка откладывается до установки Python. Удаление и проверка VPN при отсутствии Python останавливаются с пояснением.

Обновлённые системные пакеты и установленный Python сохраняются при откате настроек VPN. Для установки пакетов серверу нужен доступ к его репозиториям APT. Локальному компьютеру для запуска самого приложения по-прежнему нужен Python 3.9 или новее.


SSH-доверие хранится локально в `~/.vpnai/ssh-hosts.json` (Windows: `%USERPROFILE%\.vpnai\ssh-hosts.json`). Там только адреса, порты и публичные отпечатки. Изменённый ключ останавливает подключение до передачи пароля. Правила первого доверия и переустановки сервера: [SSH_TRUST.md](SSH_TRUST.md).


## Удаление и повторный запуск — v0.1.10

1. Закройте старое приложение и запустите новую сборку.
2. Укажите ту же пару серверов и выберите «Удалить установку».
3. Подтвердите операцию словом **УДАЛИТЬ** и дождитесь результата.

Приложение сначала проверяет оба сервера, затем создаёт на обоих закрытые
резервные архивы `/root/ovpn-backup-*.tar.gz`. До успешного завершения этих
этапов службы не останавливаются. Используется код удаления из новой сборки,
даже если на сервере остался скрипт старой версии.

Зарубежный сервер не требует `ipset` или `nginx`. Повторный запуск учитывает
частичное удаление, включая сбой прежнего установщика без этих программ.
Успешно очищенный сервер определяется по `/var/lib/ovpn-installer-removal.json`;
отметка содержит роль, IP пары и путь к резервной копии, без паролей и ключей.
Не удаляйте отметку и резервную копию до завершения операции на обоих серверах.

Удаляются компоненты своей установки. Системные пакеты и закрытые архивы
остаются. Архивы могут содержать ключи и пароли: не публикуйте их.


## Повторная установка после удаления — v0.1.11

Если предыдущая операция завершилась ошибкой «RU: занят нужный порт 80»,
но в отчёте удаление обоих серверов отмечено как завершённое, запустите
v0.1.11 и выберите «Установить VPN» с той же парой серверов.

Оставшийся штатный nginx повторно используется только после проверки
отметки удаления своей установки, владельца порта 80 и конфигурации без
дополнительных сайтов. Другие занятые порты и веб-службы по-прежнему
блокируют установку. Не нужно вручную останавливать nginx или удалять его.
При последующем удалении ожидание завершения IPsec ограничено 20 секундами.


## HTTPS и автоматическое продление — v0.1.13

После сбоя выпуска сертификата закройте старое приложение, запустите новую
сборку и выберите восстановление установки с той же парой серверов и прежними
режимами. Пользователи и ключи сохраняются. При отсутствии сохранённой установки
выберите обычную установку.

Действующий сертификат `/etc/letsencrypt/live/ovpn-links/fullchain.pem`
повторно используется, если до истечения остаётся не менее суток, IP совпадает,
цепочка доверена, ключ соответствует сертификату и сохранена конфигурация
продления Certbot. Приватный ключ и учётная запись ACME остаются на RU.

На NL устанавливается `ovpn-acme-proxy.service`. Он слушает только GRE-адрес
на TCP 18765, принимает только RU через защищённый туннель и разрешает CONNECT
только к production/staging API Let’s Encrypt на 443. Публичный порт 18765
открывать не нужно. TLS остаётся сквозным от RU до Let’s Encrypt.

Автопродление работает на серверах без открытого приложения на компьютере.
`ovpn-cert-renew.timer` проверяет продление каждый час, с небольшой случайной
задержкой и после загрузки. Обёртка `/usr/local/sbin/ovpn-cert-manage.py`
использует NL, при недоступности пробует прямой доступ. Обновляется только
сертификат `ovpn-links`, без принудительного перевыпуска. Сетевой сбой допускает
одну повторную попытку; ограничения CA и ошибка HTTP-подтверждения не вызывают
немедленных повторов. Следующая часовая проверка выполняется автоматически.

При успешном выпуске или продлении deploy-hook проверяет конфигурацию и
перечитывает nginx. При неудаче текущий сертификат сохраняется, службы OpenVPN
не останавливаются. Для HTTP-подтверждения TCP 80 на RU должен оставаться
доступным из интернета. NL и защищённый туннель нужны для запасного маршрута
к API; полную сетевую недоступность обоих маршрутов программа устранить не может.

Проверка на RU после успешной установки:

```sh
systemctl list-timers --all ovpn-cert-renew.timer
journalctl -u ovpn-cert-renew.service -n 30 --no-pager
cat /var/lib/ovpn-cert/status.json
python3 /usr/local/sbin/ovpn-cert-manage.py probe
openssl x509 -in /etc/letsencrypt/live/ovpn-links/fullchain.pem -noout -dates
```

`probe` только проверяет доступность API, сертификат не выпускает. Результат
содержит `available` и `transport` (`nl` либо `direct`). `status.json` содержит
время последней попытки, действие и результат, без секретов. Проверка службы
канала на NL: `systemctl status ovpn-acme-proxy.service --no-pager`.

Механизм `renew` и deploy-hook: [официальная документация Certbot](https://eff-certbot.readthedocs.io/en/stable/using.html#renewing-certificates).
