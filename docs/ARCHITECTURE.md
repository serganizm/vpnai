# Как работает VPNAI

## Локальное приложение

`macos.command`, `linux.sh` и `windows.bat` запускают `app/app.py`. Если установлен SSH-компонент, используется Python из `app/.venv`; иначе системный Python позволяет пройти демонстрацию.

HTTP-сервер слушает только `127.0.0.1`. При запуске создаётся случайный токен, который передаётся браузеру в URL-фрагменте и используется в заголовке запросов API. Проверяются Host и Origin. Интерфейс не использует внешние шрифты, CDN и JavaScript-библиотеки.

`app/static/` содержит четыре шага: серверы, настройки VPN, ручные списки, сводка/прогресс. Основная логика находится в `app/backend.py`; установочные функции и серверные шаблоны — в `app/core/`.

## SSH и операция

Реальные операции выполняются через Paramiko. Публичные ключи SSH-серверов автоматически читаются без авторизации перед запуском операции. Новый ключ требует подтверждения первого доверия (TOFU), после чего его отпечаток сохраняется в локальной базе ~/.vpnai/ssh-hosts.json. Известный ключ проверяется автоматически; изменившийся ключ блокирует запуск. Само SSH-соединение повторно проверяет ключ, поэтому замена между получением и авторизацией также отклоняется. Подтверждение привязано к выданному приложением одноразовому токену на 5 минут; пароли и приватные ключи в нём не сохраняются.

Доступны пароль, вставленный приватный ключ и чтение локального файла ключа. SSH-пароли и введённые ключи не записываются в локальные файлы/отчёт. Команды `ssh-copy-id`/PowerShell только формируются и копируются в буфер; пользователь выполняет их сам.

Установка выполняется в фоновом потоке процесса. Вкладка опрашивает состояние. На обоих серверах удерживается блокировка операции. Приложение сначала проверяет доступ/ОС, готовит Python, определяет сохранённую установку и конфликты, затем применяет файлы и запускает проверки.

Незавершённая установка сохраняет состояние и ключи для восстановления. Команда остановки проверяется между этапами. Потеря процесса приложения или SSH-соединения требует повторной проверки состояния серверов.

## Российский сервер

- OpenVPN UDP и TCP принимают клиентов в разных приватных подсетях.
- Каждый пользователь имеет индивидуальный сертификат, CRL обеспечивает отзыв доступа.
- В режиме с паролем дополнительно проверяются логин/пароль и соответствие сертификата пользователю.
- Netfilter/ipset классифицируют назначения и ставят метки соединений; policy routing выбирает прямой российский выход либо GRE.
- GRE защищён IPsec в транспортном режиме; передача открытого GRE между серверами блокируется правилами.
- HTTPS и временный сервис выдачи файлов обслуживают ссылки, создаваемые серверным меню.

## Зарубежный сервер

На нём работают IPsec, GRE, обратные маршруты к подсетям OpenVPN и NAT выхода в интернет. OpenVPN-клиенты непосредственно к нему не подключаются в этой схеме.

## Списки и клиентские маршруты

Источник IPList — `https://iplist.opencck.org/?format=json&data=cidr4`. Загруженные CIDR проверяются и сохраняются отдельно от ручных списков:

```text
/etc/ovpn-routing/force-ru.txt       Ручной RU
/etc/ovpn-routing/extra-nl.txt       Ручной RU-EU
/var/lib/ovpn-routing/source.json   Автоматический IPList
```

Для раздельного режима формируется точное объединение IPv4 CIDR без захвата дополнительных адресов и без маршрута по умолчанию. Адрес VPN-транспорта российского сервера исключается. Маршруты выдаются клиенту при подключении, поэтому после изменения списков требуется переподключение.

В режиме полного VPN клиент получает IPv4 default route. Вариант «всё через зарубежный» меняет классификацию выхода, сохраняя ручные файлы для других режимов. IPv6 и системный выбор DNS этой версией не перенастраиваются.

## Где находятся рабочие файлы

```text
/root/menu.sh                         Серверное меню
/root/ovpn-profiles/                   Профили и credentials.txt
/etc/openvpn/server/                   Настройки UDP/TCP, пользователи, PKI
/usr/local/libexec/ovpn-menu.py        Код меню
/usr/local/sbin/ovpn-*                Управление пользователями, сетью и списками
/etc/swanctl/conf.d/ovpn-gre.conf      IPsec
/var/lib/ovpn-installer/              Состояние и сведения о владельце файлов
/var/lib/ovpn-routing/                IPList и сформированные маршруты
```

Правка сохранённого `credentials.txt` не меняет пароль в базе. Пароль меняется через серверное меню. Сам `.ovpn` содержит приватный ключ пользователя и должен храниться как секрет.

## Отчёт и скачивание

Отчёт содержит выбранные режимы, этапы, сведения о подготовке ОС и результаты серверных проверок. Пароли SSH в него не включаются. Архив профилей передаётся с российского сервера по SSH и находится в памяти приложения до 10 минут.

Демонстрация использует отдельный код симуляции: не подключается к VPS и создаёт архив только с пояснением и планом. Её успешное завершение не означает установки реального VPN.

## Границы проверки

Серверная проверка проверяет службы, HTTPS и выходы из изолированных сетевых пространств для подсетей UDP/TCP. Она не выполняет полноценное подключение OpenVPN Connect с личного устройства. Полную SSH-установку текущей веб-версии на чистых VPS ещё нужно проверить отдельно.
