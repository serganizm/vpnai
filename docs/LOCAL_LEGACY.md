# Чтение и обновление действующей установки — VPNAI 0.5.1

При выборе «Обновить/Восстановить» текущие настройки и ручные списки считываются автоматически. При переходе на «Маршруты» они перечитываются, если вы ещё не меняли загруженные параметры. Автоматическое чтение не сбрасывает ваш выбор способа входа или отредактированные списки. Кнопка ручной загрузки заменяет форму актуальными данными сервера.

Установки без state.json/owned.json распознаются по реальным файлам OpenVPN, GRE и генератору профилей. Для них в версии 0.5.1 поддерживается отдельная смена входа — сертификат с паролем или только сертификат — и выбор DNS. Порт, маршрутизация, списки и компоненты VPN сохраняются. DNS меняется только если вы включили его в операцию кнопкой «Применить выбранный DNS»; иначе остаётся прежним. Редактирование маршрутов доступно в «Управление». Полное обновление компонентов старой установки этой сборкой не выполняется.

Смена входа запускается только кнопкой обновления после просмотра параметров и подтверждения. Создаётся закрытая резервная копия изменяемых конфигураций и профилей в /root/ovpn-auth-backups/. Перезапускаются только ранее активные OpenVPN-службы. Пользователи, их пароли, сертификаты и ключи не пересоздаются; недостающие профили автоматически не создаются. При ошибке восстанавливаются исходные файлы. После успеха скачайте обновлённые конфигурации и импортируйте их на устройства.

Чтение не создаёт файлы состояния установщика и не присваивает программе владение существующей установкой. После ошибки сначала перечитайте настройки. Возможности доступны на Android, macOS, Linux и Windows. Подготовка релиза не применяет настройки VPN к серверам.

## DNS при обновлении

DNS-блок одинаково доступен для установки и обновления. Выберите провайдера и нажмите «Применить выбранный DNS»; выбор появится на странице подтверждения. «Сохранить текущий DNS» исключает изменение DNS из операции. Доступность выбранных DNS с EU проверяется до смены входа. Затем отдельно применяются вход и DNS; при ошибке второго этапа результат входа сохраняется, а операция завершается с явным сообщением о частичном результате. Перечитайте настройки перед повторением. Во время подготовки сборки ни смена входа, ни DNS на реальных серверах не применяются.

## Автоматическое чтение DNS и управления

DNS считывается в том же запросе, что и текущие настройки обновления. В DNS-блоке видны реальные серверные адреса; чтение не включает изменение DNS в операцию. При открытии «Управления» и его страниц перечитываются состояние серверов, пользователи, маршруты и DNS. Уже изменённый выбор DNS не сбрасывается автоматическим чтением. Для явной перезагрузки остаются кнопки чтения. При ошибке показано, что DNS не удалось считать, вместо предположения «DNS клиента».


## Освобождение SSH-блокировки

После штатного завершения, ошибки или отмены приложение в `finally` отправляет служебному процессу команду освобождения и ждёт подтверждение перед закрытием SSH. При обрыве связи служебная аренда истекает через 45 секунд после последнего сигнала; сигналы отправляются каждые 10 секунд. Пока реальная серверная команда ещё работает, она сохраняет общий дескриптор блокировки: параллельная операция не допускается. Следующая команда без действующей блокировки не запускается. Файл `/run/ovpn-installer.lock` не удаляется: доступность определяется блокировкой ядра, а не наличием файла.

Для первоначальной установки на сервер без Python используется отдельная блокировка на время команды; после установки Python приложение переходит на аренду.


## Лимиты подключений 0.5.1

Общий лимит — в установке и «Управление → Маршрутизация»; индивидуальный — в меню пользователя. Первый запуск функции на старой установке потребует переподключить устройства после подтверждения. Дальнейшее уменьшение лимита сохраняет текущие сеансы. Подробнее: [CONNECTION_LIMITS.md](CONNECTION_LIMITS.md).
