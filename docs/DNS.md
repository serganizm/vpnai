# DNS для VPN-клиентов — VPNAI 0.3.3

DNS-настройки доступны в Windows, macOS, Linux и Android. Серверная настройка общая для пользователей OpenVPN UDP и TCP.

## Проверка действующего VPN

1. Подключитесь к RU/EU в «Подключении».
2. Откройте «Управление → Маршрутизация → DNS» и нажмите «Считать с сервера».
3. Выберите Google, Cloudflare или один/два своих публичных IPv4. Кнопка «Проверить доступность» отправит DNS-запросы по UDP и TCP 53 с EU-сервера; настройки она не меняет.
4. Нажмите «Применить DNS» и подтвердите разрыв текущих VPN-подключений. Приложение повторит проверку DNS и создаст закрытую копию файлов в /root/ovpn-dns-backups/.
5. Переподключите OpenVPN for Android на телевизоре. В журнале клиента проверьте получение dhcp-option DNS и маршрутов к DNS, затем попробуйте YouTube. Если профиль игнорирует настройки сервера, его нужно исправить. Работа YouTube от одной смены DNS не гарантируется.

«DNS клиента» убирает передачу DNS от сервера и отдельные DNS-маршруты. Это не возвращает старые ручные DNS автоматически. Чтобы вернуть прежние адреса, считайте их до изменения и выберите их снова; полная копия прежних файлов также остаётся на сервере.

## Как применяется

DNS передаётся обоим OpenVPN-профилям. В списки RU/EU приложение не пишет. Для выбранных DNS добавляются /32-маршруты клиентам и отдельные серверные policy rules для подсетей UDP/TCP. DNS-трафик направляется через существующий GRE на EU; в отдельной таблице есть unreachable fallback. При запуске OpenVPN система сначала поднимает DNS-политику; при её ошибке запуск OpenVPN блокируется, вместо работы без нужных правил. Локальный resolver ОС сервера не меняется.

Применение меняет ru.conf и ru-tcp.conf, создаёт /etc/ovpn-routing/dns.json, /usr/local/sbin/ovpn-dns-policy, ovpn-dns.service и два systemd drop-in. Перезапускаются только ранее активные службы OpenVPN. Если применение завершается ошибкой, приложение пытается восстановить файлы, правила и активные службы. При неполном откате оно сообщает об этом и показывает путь к копии. При обрыве SSH результат может быть неизвестен: сначала считайте настройки заново, не применяйте повторно вслепую.

Требуется совместимая пара конфигураций ru.conf/ru-tcp.conf и существующий маршрут в таблице 310 через GRE к выбранному EU. При занятых служебных ресурсах (таблица 31220, приоритет 10220), конфликтующих более ранних policy rules или нестандартном формате приложение откажется применять настройку. Сторонние маршруты не удаляются. Частные IPv4 и IPv6 DNS пока не поддержаны.

## Установка, обновление и архивы

В установке DNS включается только кнопкой «Использовать при установке» и применяется при запуске изменяющей операции. Без неё сохраняется DNS текущей установки, а новая установка не передаёт DNS. При ошибке отдельного DNS-этапа установившийся VPN не удаляется: отчёт просит уточнить состояние DNS. Обычные проверки серверов/VPN DNS не применяют.

Перед восстановлением архива с активным управляемым DNS сначала выберите «DNS клиента» и примените его. DNS из копии применяется после восстановления. Удаление VPN через эту версию приложения останавливает DNS-службу и очищает её правила; старые серверные скрипты удаления могут не знать об этих компонентах.

## Границы проверки

Поддержка настроек проверяется изолированными тестами. В этой сессии реальные VPS не изменялись. Полноценную проверку DNS с телевизора и после перезагрузки VPS выполняйте отдельно. Не перезагружайте рабочие серверы только ради первого теста. DoH/Private DNS и отдельные приложения могут обходить настройки VPN. Выбор нескольких DNS не гарантирует строгий порядок обращений клиента.

Если прежняя версия оставила DNS-правила без DNS-файла после ошибки, приложение показывает предупреждение. Следующее подтверждённое применение может обработать только точно распознанные правила этой программы: файлы должны совпадать с её резервной копией, а подсети, DNS-адреса и GRE-маршрут — соответствовать текущей установке. Чтение ничего не исправляет автоматически.

Стандартное правило IPsec с приоритетом 220 и пустой таблицей 220 сохраняется и не мешает применению DNS. Поддерживаются оба формата подсетей Linux: CIDR и отдельные поля src/srclen.

При ошибке OpenVPN for Android «Used x 101 tries to get current version … of the profile» попробуйте принудительно остановить приложение, очистить только кэш и повторно импортировать файл под новым именем профиля. Такая ошибка относится к чтению профиля на устройстве; не нужно ради неё менять сервер или создавать нового пользователя.
