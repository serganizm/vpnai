# Проверки 0.3.2

## Автоматические проверки

Команда: `python -m unittest discover -s app/tests -v`. Тесты используют подмену SSH, временные каталоги и локальный HTTP API, не изменяя VPS. Проверяются валидация, доверие SSH, память сеанса, пользователи, пароли, маршруты, резервные копии, обновление, удаление и сертификаты.

Добавлены регрессии диагностики: работающий VPN без state.json/owned.json, существующий маршрут 10.77.0.0/24, запрет вызова установочного preflight и сетевых тестов engine.verify для check/verify, отсутствие серверного lock-файла, чтение реального порта ss, отсутствие ключей в отчёте, отличие неизвестного результата от успешного.

В GitHub Actions каждая desktop-сборка проходит тесты своей ОС и автономный запуск без соседнего app/ или .venv: криптография, локальный HTTP API, встроенные инструкции, защита токеном и сеанс в памяти. Android проверяется локально в Android 15 ARM64-эмуляторе: Python/Paramiko, криптография, API, WebView, сохранение документа и перезапуск сеанса.

Публикация выполняется после успешных native-проверок. APK сверяется с тегированными исходниками по каждому файлу встроенного payload, а служебный manifest JSON — по содержимому без зависимости от порядка ключей. Общий ZIP содержит те же четыре приложения; SHA256SUMS.txt покрывает файлы релиза.

## Границы проверки

Не выполняются установка или изменение реальных VPS, проверка всех моделей телефонов, всех версий ОС, провайдеров или сквозное подключение OpenVPN Connect. Диагностика check/verify не заменяет клиентскую проверку VPN. Неудача ping может означать фильтрацию ICMP; такой результат неполный. Недоступность swanctl может означать другой IPsec backend.

Отчёты с отсутствием state.json и конфликтом 10.77.0.0/24 использованы как регрессионный сценарий; окончательное подтверждение на пользовательских серверах требует повторного запуска исправленной версии пользователем.
